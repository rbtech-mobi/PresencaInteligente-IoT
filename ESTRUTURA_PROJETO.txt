VISÃO GERAL
===========
Aplicação Android profissional para automação inteligente baseada em geolocalização.
Sincroniza estado de AC em tempo real via MQTT com suporte a background automation.

Arquitetura: MVI (Model-View-Intent) + Repository Pattern
Build System: Gradle KTS
Compose: Material Design 3
Target Android: API 26+ (Android 8.0+)

FLUXOS PRINCIPAIS
=================

1. Inicialização da App
   ┌─ MainActivity.onCreate()
   ├─ ViewModelProvider → PresenceViewModel
   ├─ checkPermissions() → RequestMultiplePermissions
   └─ setContent() → AppNavigation(viewModel)

2. Navegação entre Telas
   ┌─ AppNavigation Composable (mutableStateOf)
   ├─ currentScreen.value = "presence"
   ├─ PresenceScreen → botão "Configurar Casa"
   ├─ currentScreen.value = "location_setup"
   ├─ LocationSetupScreen → "SALVAR"
   ├─ onLocationSaved() → presenceViewModel.setHomeLocation()
   └─ currentScreen.value = "presence"

3. Sincronização MQTT
   ┌─ MqttRepository.connect()
   ├─ client.setCallback(MqttCallbackExtended)
   ├─ client.subscribe("home/ac/status")
   ├─ messageArrived(topic, payload)
   ├─ updateInternalState(json)
   ├─ _deviceState.update { ... }
   └─ PresenceScreen observa via collectAsState()

4. Automação Geofence
   ┌─ GeofenceManager.setHomeLocation(lat, lng, 1000m)
   ├─ PendingIntent → GeofenceBroadcastReceiver
   ├─ onGeofenceTransition()
   ├─ PresenceService.startCommand()
   ├─ startAutomationMonitoring()
   ├─ mqttRepository.deviceState.collect()
   ├─ IF AC OFF → publishCommand("on", temp)
   └─ updateNotification()

5. Persistência de Coordenadas
   ┌─ LocationSetupScreen → entrada manual
   ├─ validação(-90/90, -180/180)
   ├─ onLocationSaved(lat, lng)
   ├─ presenceViewModel.setHomeLocation()
   ├─ locationRepository.saveHomeLocation()
   ├─ DataStore.edit() → HOME_LATITUDE, HOME_LONGITUDE
   └─ homeLocationFlow observa mudanças


PADRÕES DE DESIGN
=================

Singleton (Thread-safe)
├─ MqttRepository
│   private constructor
│   companion object getInstance() { synchronized(this) }
│
└─ LocationRepository
    private constructor
    companion object getInstance() { synchronized(this) }

State Management (Reactive)
├─ PresenceViewModel
│   _uiState = MutableStateFlow(PresenceUiState())
│   uiState = _uiState.asStateFlow() (observável)
│
└─ MqttRepository
    _deviceState = MutableStateFlow(DeviceState())
    deviceState = _deviceState.asStateFlow() (observável)

MVI Pattern
├─ State: PresenceUiState (imutável, 1 única fonte verdade)
├─ Action: PresenceAction (sealed interface de intenções)
└─ ViewModel: onAction(action) → _state.update()

Repository Pattern
├─ Data source único: MqttRepository (MQTT)
├─ Data source único: LocationRepository (DataStore)
└─ Sincronização: geofenceManager orquestra ambos

Coroutines + Flows
├─ viewModelScope.launch para operações assíncronas
├─ withContext(Dispatchers.IO) para I/O
├─ Flow<T> para observabilidade
└─ StateFlow<T> para estado observável

FLUXO DE DADOS (Exemplo)
=======================

Usuário clica "LIGAR AR":
  1. PresenceScreen → onToggle()
  2. viewModel.onAction(OnToggleAcClick)
  3. PresenceViewModel.toggleAcPower()
  4. sendCommand("on", targetTemp)
  5. mqttRepository.publishCommand("on", 22)
  6. MQTT client publica em "home/ac/command"
  7. Broker roteia para ESP32
  8. ESP32 liga AC
  9. ESP32 publica estado em "home/ac/status"
  10. Cliente MQTT recebe mensagem
  11. MqttCallbackExtended.messageArrived()
  12. updateInternalState(json)
  13. _deviceState.update() emite novo estado
  14. PresenceScreen observa via collectAsState()
  15. UI rerendering automático (isAcOn = true)

ESCALABILIDADE
==============

Para adicionar novos Comandos MQTT:
  1. Adicionar novo case em PresenceAction
  2. Implementar em PresenceViewModel.onAction()
  3. Chamar mqttRepository.publishCommand()

Para adicionar novas Telas:
  1. Criar <Tela>ViewModel + PresenceAction
  2. Criar <Tela>Screen Composable
  3. Adicionar case em AppNavigation
  4. Adicionar navegação callbacks

Para adicionar Persistência:
  1. Estender LocationRepository com novo DataStore
  2. Expor Flow<NovosDados>
  3. Observar em ViewModel
